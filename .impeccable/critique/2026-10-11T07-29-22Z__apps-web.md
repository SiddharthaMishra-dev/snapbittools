## Design Specificity Verdict

**LLM assessment:** Interchangeable. The shell is a blue Tailwind utility kit: frosted header, dashed cloud dropzone, GitHub star pill, category links, dot grid. Privacy is a sentence and a lock icon, not a layout idea. Home, the compressor, and the JSON formatter could be swapped onto any file-utility brand without changing structure. SnapBit's actual character (files never leave the device) is contradicted by the first verb on the compressor, "Upload images".

**Deterministic scan:** `impeccable detect --json apps/web/src` exited 0 with an empty finding list. The detector did not catch the behavioral and copy problems above. That is a miss, not a clean bill of health. Those issues live in labels, disabled-but-visible toolbars, and page composition, not in the class-name patterns the scanner flags.

**Visual overlays:** None on the app. Assessment B injected `detect.js` into the Chrome connection-refused page, not into SnapBit. Console hits (`tight-leading` on a DIV, and one "No anti-patterns found") are false positives from `chrome-error://`. The live server on port 8400 was stopped. Do not look for highlights in the browser.

## Overall Impression

The empty compressor is the best moment in the product: one heading, one sentence, "Select Images", and a lock line. Everything around that moment works against it. The tool sits inside a marketing article, the privacy promise uses the word "upload", and the JSON formatter leads with seven controls before a single paste.

## What's Working

- The empty dropzone copy is clear: "Drag and drop photos here, or choose files to compress." plus "Processed in your browser. Nothing is uploaded to a server."
- The quality slider has ends labeled "Smaller file" and "Higher quality", a live percentage, and a note about PNG staying lossless at 100%.
- JSON output stays next to input, with placeholder `Paste your JSON here, e.g., {"name": "John", "age": 30}`, and Format, Minify, Copy, and Clear stay disabled until there is text.

## Priority Issues

### [P1] The tool is an island in an SEO page
- **Why it matters:** On `/image-compressor` the sidebar already lists every tool plus a Blogs group. Below the dropzone the page continues through Key Benefits, Common Use Cases, FAQs, "Also useful for" (50KB, 100KB, 200KB, JPEG, PNG, web, optimize), and Other Image tools. The same pattern repeats on the JSON formatter. A person who came to compress a file has to find the dropzone inside an article.
- **Fix:** Keep the work surface as the page. Move benefits, use cases, and variant links into one collapsed or end-of-page block. Do not repeat the full tool list in both the header and the sidebar.
- **Suggested command:** /impeccable distill

### [P1] "Upload images" fights the privacy promise
- **Why it matters:** The live heading is "Upload images". The next line says nothing is uploaded. That lock line unmounts once files are added, so the reassurance disappears during the actual work.
- **Fix:** Rename the title to "Drop images" and the button to "Choose images". Keep the lock line pinned under the file list.
- **Suggested command:** /impeccable clarify

### [P1] The JSON bar is the product
- **Why it matters:** Before any paste, the bar shows Quotes (`"` and `'`), Format, Minify, Copy, Download CSV, Clear, and Fullscreen. Format and Minify both write back into Input even though Output already shows the result. "Download CSV" belongs on JSON to CSV, not on a formatter.
- **Fix:** Make Copy the only primary action. Put quote style, Minify, Download CSV, and Fullscreen in one overflow menu. Stop writing back into Input unless the user chooses "Replace input".
- **Suggested command:** /impeccable distill

### [P1] Compression has no stable result
- **Why it matters:** Dropping files starts compression immediately. Changing Quality or "Preserve original format" marks every file "Ready" and recompresses, so there is no A/B against the previous size. There is no per-file remove and no "add more". The ratio is computed and not shown. `setIsDownloadingZip(true)` is never called, so "ZIPPING..." cannot appear; the button only resets the flag in `finally`.
- **Fix:** Add a per-row remove, an "Add images" action, and show original size, new size, and ratio. Debounce setting changes into a "Settings changed — recompress" state. Set the zip flag true before `generateAsync`.
- **Suggested command:** /impeccable harden

### [P2] Errors are browser alerts
- **Why it matters:** "Please select valid image files", "No compressed files available for download.", and "Failed to create ZIP file" are `alert()` calls. A bad JSON paste shows the engine message with no suggested fix. The same alert pattern is copied across the converter, base64, CSV, renamer, and HTML minifier.
- **Fix:** Render the message on the dropzone or the file row, name the file, and keep the user's text.
- **Suggested command:** /impeccable clarify

## Persona Red Flags

**Alex (power user):** Ctrl+K searches tools, but Copy, Format, and Minify have no shortcuts. The quality slider recompresses the whole batch, so the previous size is gone. "Clear All" is the only way to drop one bad file. The compression ratio is never shown. "Download CSV" sits on the formatter.

**Jordan (first-timer):** The first heading says "Upload images" and the lock line says the opposite. Quote buttons are a bare `"` and `'`. A bad drop is a browser alert. After success, the per-file download is an unlabeled icon. "Invalid JSON" then shows the parser's own sentence.

**Casey (mobile):** Primary actions (sidebar toggle, JSON toolbar, "Select Images") sit at the top. The dropzone uses `p-12`. Trust badges on the home page are hidden below `sm`. Input is a tall box and Output stacks under it. Refresh drops both the images and the JSON.
